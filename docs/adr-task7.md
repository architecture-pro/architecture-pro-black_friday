## 1. Коллекция orders

```javascript
{
  _id: "order-101",
  user_id: "user-123",
  created_at: ISODate("2026-10-29T10:00:00Z"),
  items: [
    {
      product_id: "product-101",
      name: "Смартфон X",
      quantity: 1,
      unit_price: NumberDecimal("59990.00")
    }
  ],
  status: "created",
  total_amount: NumberDecimal("59990.00"),
  geo_zone: "moscow"
}
```

### Шард-ключи

- `_id` — поиск истории потребует обращения к нескольким шардам
- `user_id` — подходит для поиска истории заказов конкретного пользователя
- `geo_zone` — возможна неравномерная нагрузка из-за популярности отдельных регионов
- `created_at` — последовательные вставки могут концентрироваться на одном шарде при диапазонном шардировании

**Шард-ключ:** `{ user_id: "hashed" }`

**Стратегия:** хешированное шардирование

### Команда MongoDB

```javascript
sh.shardCollection('shop.orders', {
	user_id: 'hashed',
});
```

### Обоснование

- Хеширование распределяет пользователей между шардами
- Поиск истории по `user_id` может быть направлен на конкретный шард
- Снижается риск концентрации новых заказов на одном шарде
- Поиск заказа только по `_id` без `user_id` может затрагивать все шарды

## 2. Коллекция products

```javascript
{
  _id: "product-101",
  name: "Смартфон X",
  category: "smartphones",
  price: NumberDecimal("59990.00"),
  stock: {
    moscow: 50,
    ekaterinburg: 40,
    kaliningrad: 30
  },
  attributes: {
    color: "black",
  }
}
```

### Шард-ключи

- `_id` — уникальный идентификатор, высокая кардинальность
- `category` — подходит для поиска по категориям, но может создавать неравномерную нагрузку
- `price` — подходит для диапазонных запросов, но цена может изменяться

**Шард-ключ:** `{ _id: "hashed" }`

**Стратегия:** хешированное шардирование

### Команды MongoDB

```javascript
sh.shardCollection('shop.products', { _id: 'hashed' });

db.getSiblingDB('shop').products.createIndex({
	category: 1,
	price: 1,
});
```

### Обоснование

- Равномерное распределение товаров между шардами
- Адресная маршрутизация запросов и обновлений по `_id`
- Снижение риска перегрузки отдельного шарда из-за популярной категории
- Составной индекс `{ category: 1, price: 1 }` ускоряет поиск товаров по категории и диапазону цен внутри шардов

## 3. Коллекция carts

```javascript
{
  _id: "cart-101",
  user_id: "user-123",
  session_id: null,
  items: [
    {
      product_id: "product-101",
      quantity: 2
    }
  ],
  status: "active",
  created_at: ISODate("2026-10-29T10:00:00Z"),
  updated_at: ISODate("2026-10-29T10:15:00Z"),
  expires_at: ISODate("2026-11-28T10:15:00Z")
}
```

### Шард-ключи

- `_id` — уникальное значение для каждой корзины, высокая кардинальность
- `user_id` — подходит для пользовательских корзин, но не для гостевых
- `session_id` — подходит для гостевых корзин, но не для пользовательских
- `status` — низкая кардинальность, возможна неравномерная нагрузка

### Выбранная стратегия

**Шард-ключ:** `{ _id: "hashed" }`

**Стратегия:** хешированное шардирование

### Команды MongoDB

Шардирование коллекции:

```javascript
sh.shardCollection('shop.carts', {
	_id: 'hashed',
});
```

Индексы для поиска корзин:

```javascript
db.getSiblingDB('shop').carts.createIndex({
	user_id: 1,
	status: 1,
});

db.getSiblingDB('shop').carts.createIndex({
	session_id: 1,
	status: 1,
});
```

TTL-индекс:

```javascript
db.getSiblingDB('shop').carts.createIndex(
	{ expires_at: 1 },
	{ expireAfterSeconds: 0 },
);
```

### Обоснование

- Хеширование по уникальному `_id` помогает равномерно распределять корзины между шардами
- Стратегия одинаково подходит для гостевых и пользовательских корзин
- Обновление содержимого и статуса корзины не требует изменения шард-ключа
- Дополнительные индексы ускоряют поиск активных корзин по `user_id` и `session_id` внутри шардов
- TTL-индекс обеспечивает автоматическую очистку устаревших корзин
