## 1. Выявление и устранение «горячих» шардов

70% запросов к товарам приходится на категорию `smartphones`. Это может создавать неравномерную нагрузку на шарды MongoDB
В коллекции `products` шард-ключ `{ _id: "hashed" }`, который равномерно распределяет товары, но не гарантирует равномерную нагрузку от запросов

## 2. Метрики мониторинга

| Метрика            | Назначение                          |
| ------------------ | ----------------------------------- |
| CPU                | Загрузка процессора                 |
| Operations/sec     | Количество операций на каждом шарде |
| Read/write latency | Задержки запросов                   |
| Disk IOPS          | Нагрузка на диски                   |
| Data size          | Распределение объёма данных         |
| WiredTiger cache   | Использование кеша MongoDB          |

Диагностика встроенными командами MongoDB:

```javascript
sh.status();
db.getSiblingDB('shop').products.getShardDistribution();
db.serverStatus();
```

`serverStatus()` выполняется на узлах шардов

## 3. Механизмы устранения перегрузки

**MongoDB Balancer** — автоматически перераспределяет диапазоны данных между шардами при дисбалансе размещения
Не устраняет перегрузку от запросов к одному популярному товару. Для снижения такой нагрузки используется Redis

```javascript
sh.getBalancerState();
sh.startBalancer();
```

**Хешированное шардирование** — распределяет товары независимо от категории:

```javascript
sh.shardCollection('shop.products', { _id: 'hashed' });
```

Команда применяется при первоначальной настройке шардирования коллекции

**Redis Cache-Aside** — кеширование популярных товаров для снижения количества чтений MongoDB

**Индексы** — ускорение поиска товаров по категории и цене:

```javascript
db.getSiblingDB('shop').products.createIndex({
	category: 1,
	price: 1,
});
```

**Масштабирование** — добавление шардов или увеличение ресурсов при устойчивой перегрузке

## 4. Автоматизация

- MongoDB Balancer автоматически устраняет дисбаланс размещения данных
- Метрики периодически проверяются для выявления перегруженных шардов
- При превышении порогов выполняется анализ запросов и принимается решение об оптимизации или масштабировании
